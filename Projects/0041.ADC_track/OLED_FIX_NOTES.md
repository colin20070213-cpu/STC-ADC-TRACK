# OLED 只有虚线的排查与修复

日期：2026-10-22。现象：上电的 W.PIE 图案和菜单均不能正常显示，只看到两条虚线。

## 坐标依据

已读取用户提供的 [PPT](https://xv25fr194gj.feishu.cn/wiki/Shi6wxXwIiz4Saky421cbogMnYg?from=from_copylink)，共 56 页。第 13、14 页的调用示例表明：

```c
LCD_P6x8Str(0, 3, "Hello");     /* 第 0 列、第 3 页。 */
LCD_PrintFloat(24, 2, 3.141, 4); /* 第 24 列、第 2 页。 */
```

本工程调用接口是 `LCD_Set_Pos(column, page)`：第一个参数为列 0～127，第二个参数为页 0～7；每页包含竖直方向的 8 个像素。页号并不是单个像素的纵坐标。应用刷新时使用 `cursor % 128` 作为列、`cursor / 128` 作为页，这一顺序正确。

## 已确认的软件问题

1. 原 `LCD_Init()` 发送 `0x20, 0x00` 选择水平寻址，而 `LCD_Set_Pos()` 和清屏、图案显示使用 `B0～B7` 页定位命令。修复为 `0x20, 0x02` 页寻址，使初始化与后续写显存方式一致。
2. 原列低位命令为 `(column & 0x0F) | 0x01`，例如第 0、1 列都会定位到第 1 列，第 2、3 列都会定位到第 3 列。改为直接发送 `column & 0x0F`。
3. 全屏填充、清屏和 W.PIE 显示统一使用修正后的定位函数；图案每页定位一次，连续发送 128 字节。保留原始 1024 字节 W.PIE 数组及一秒显示时间。
4. 显式设置 64 行复用比；初始化时片选先置为无效。头文件补全底层接口声明，避免应用自行重复声明。

控制器命令的依据为 [Solomon Systech SSD1306 数据手册](https://www.olimex.com/Products/Modules/LCD/MOD-OLED-128x64/resources/SSD1306.pdf) 的寻址方式、列地址及页地址章节。本次按现有驱动采用的命令集修复，未通过实物识别屏幕控制器型号。

## 修改范围与备份

- 共享库只修改 `Libraries/boards/src/LCD.c`、`Libraries/boards/inc/LCD.h`。原库编码及版权声明保留。
- 应用只调整 `USER/src/track_app.c` 的接口声明，固件使用库头文件中的正式声明。
- 全部 43 个原库文件、58 个工程文件引用保留；原 W.PIE 数组未改变。
- 修改前源码及 HEX 备份：`MDK/before-oled-fix.zip`。
- 库文件核对结果：`MDK/oled-fix-verification.json`。

共享库修复也会被引用同一 `LCD.c` 的其他工程在下次编译时使用；本次没有编辑其他工程文件。

## 验证与实机边界

新增 `tests/test_lcd.c`，直接编译真实 `LCD.c` 和 `Font.c`，在 GPIO 时钟上升沿还原实际四线 SPI 字节，并送入控制器显存模型。检查项目包括：上电一秒时显存与原 W.PIE 数组一致、随后清屏、全部 1024 个页列地址单独写入、全屏填充、指定位置文本、应用所用八字节分片刷新，以及越界定位保护。

`tools/test.ps1` 中的 OLED 总线测试及原 PID、双/四电感、菜单、硬件层、Flash 兼容性测试均通过。`tools/build.ps1` 完整编译通过，0 错误、0 警告；HEX 校验及参数 Flash 扇区避让检查通过。

输出固件：`MDK/Objects/Project_Template.hex`。本次未执行实机烧录；模拟测试不能验证真实接线、供电、电平、串行时序或屏幕型号，因此尚不能断言这两处软件问题是实机虚线现象的全部原因。

烧录后先观察一秒 W.PIE 图案，再检查主菜单及上下翻页。若仍只有虚线，下一步应核对屏幕接口与引脚，并采集初始化时的串行波形：CS=P22、数据=P23、RST=P24、CLK=P25、DC=P26。
