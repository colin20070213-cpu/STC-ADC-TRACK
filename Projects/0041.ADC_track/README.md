# 四电感电磁循迹比赛程序

适用 STC32G12K128，工程入口为 `MDK/Project_Template.uvproj`，固件输出为 `MDK/Objects/Project_Template.hex`。
保留全部共享 Libraries 及原库版权声明；本次修复共享 `boards/src/LCD.c` 和 `boards/inc/LCD.h` 的 OLED 寻址问题，其他 Projects 未修改。详见 [OLED 排查记录](OLED_FIX_NOTES.md)。

Keil 工程保留完整 `startup / user / boards / drivers` 库分组，新增循迹代码放在 `application`。
所有库源文件、头文件和预编译库均保留工程引用，不因当前未使用而移除。
`Ci24R1` 与 `nrf24l01` 导出重名接口，保留两份源码引用，按原模板选择 `nrf24l01` 编译，`Ci24R1.c` 为可选实现，未删除。

当前为四电感版本：两侧横置 L/R，中间同平面纵置 LM/RM，ADC 每 1ms 启动整帧扫描，转向 PID 为 2ms。更新说明和接线待办见 [四电感与 1ms 采样说明](FOUR_SENSOR_GUIDE.md)。
双电感改造前版本已上传至 [GitHub 基线标签](https://github.com/colin20070213-cpu/STC-ADC-TRACK/tree/dual-stable-20261023)，包含全部原库、源码与对应 HEX。

已接入右后轮 P04/P52 单编码器速度闭环，左右电机始终共用一个 PWM。速度单位、首次设置和调参方法见 [速度闭环说明](SPEED_LOOP_GUIDE.md)。

自己上手修改前可先看 [代码阅读与修改指南](CODE_GUIDE.md)。常用配置集中在 `USER/inc/track_config.h`；PID 算法已独立为 `track_pid.h/.c`。
发车操作可直接按 [开始运行前检查与操作清单](STARTUP_CHECKLIST.md) 执行。

## 上电与按键

上电初始化后显示原库 W.PIE 图案一秒，然后进入中文分级菜单。上电期间始终停止电机和舵机输出。
启动时按住按键也会显示菜单，但必须全部松开至少 25ms 后才能操作，避免误启动。

| 方向 | 引脚 | 操作 |
|---|---|---|
| 上 | P42 | 上一项；编辑时增加 |
| 下 | P46 | 下一项；编辑时减少 |
| 左 | P45 | 退出；编辑中撤销未保存值 |
| 右 | P41 | PID/速度页进入编辑；编辑时切换精调/粗调；标定页重新采集 |
| 中 | P27 | 进入菜单项；确认并保存 |

上下键消抖 20ms，按住约 600ms 后连调；中键不连发。每屏最多显示三项，上下选择、中键进入。
设置页退出回到所属大类，子菜单左键返回主菜单，主菜单左键不动作；各级菜单保留自己的光标位置。

## 菜单结构

```text
循迹菜单
├─ 标定设置
│  ├─ 电感标定
│  └─ 居中标定
├─ PID调参
│  ├─ 转向PID调参（Kp / Ki / Kd / 恢复初值）
│  └─ 速度闭环调参（独立 Kp / Ki / Kd / 恢复初值）
├─ 舵机设置
│  ├─ 舵机中值
│  ├─ 舵机左限位
│  ├─ 舵机右限位
│  └─ 舵机方向
├─ 电机设置
│  ├─ 速度设定（基础/弯道目标计数，每 10ms）
│  ├─ 动力限幅（原基础/弯道 PWM 上限）
│  ├─ 左电机方向
│  └─ 右电机方向
└─ 开始运行
```

### 标定设置 → 电感标定

进入即采集。电机不动，舵机无脉冲。手动移动小车，让每路电感充分经历无电磁信号和强电磁信号的位置。
每行 `N` 是当前滤波后的 ADC 值，`m` 是本次最小值，`M` 是本次最大值；全部启用的通道同时显示，约 10Hz 刷新。

- 中键：校验并保存本次极值到 RAM，成功后返回菜单。
- 左键：取消本次采集，保留同次上电之前的有效标定。
- 右键：重新清空本次极值和采样计数。

放大板更换后恢复正常阈值：每路必须至少采集 250 帧（2ms/帧，约 0.5 秒），跨度至少 100 ADC，且最大值不能达到饱和区（4090 及以上）。最小跨度由 `TRACK_CAL_MIN_SPAN` 配置，确认后每路独立映射到 0～1000。
采样不足提示 `MORE SAMPLES NEEDED`；范围不足/饱和提示具体 `CH`；ADC 超时后本次标定失效，须右键重采。

当前数组顺序：1=L/P13 左横，2=R/P01 右横，3=LM 左纵，4=RM 右纵；中间引脚在配置中使用当前 P10/P05 配置，请核对实际接线，必须按实际接线修改。每路独立归一化到 0～1000。标定不会写 Flash，每次断电重启必须重新完成，否则不能开始运行。
成功保存新的电感极值会清除旧居中参考，必须重新执行“标定设置 → 居中标定”；取消或校验失败则保留原极值与居中参考。

### PID 调参

驱动层保持电机关闭，仅在标定有效且电磁信号正常时运行舵机 PID。信号消失时关闭舵机输出，信号恢复后允许继续静态调试；电机始终不动。

1. 上下选择 Kp/Ki/Kd，右键进入编辑；第四项为“恢复PID初值”，右上角显示 1/4～4/4。
2. 上下修改，右键切换 0.01 / 0.10 步长。修改即时参与静态舵机控制，`*` 表示未保存。
3. 中键保存到 Flash，提示 `SAVED OK`。失败时按阶段提示 `FLASH ERASE/WRITE/READ/VERIFY FAILED`，不假装保存成功。
4. 编辑中左键撤销本次编辑；退出编辑后再次左键回菜单，关闭舵机。

代码初值在 `track_config.h` 顶部，可直接修改实际数值：

```c
#define TRACK_PID_DEFAULT_KP   130.00f
#define TRACK_PID_DEFAULT_KI     0.00f
#define TRACK_PID_DEFAULT_KD     8.15f
```

采用方案 A：启动时有效 Flash 参数优先；没有有效记录时才自动使用代码初值。
当前代码初值为 Kp=130.00，允许上限为 500.00；Ki/Kd 上限仍为 20.00。
因此修改宏并重新下载后，若保留了 EEPROM，旧 PID 仍然生效。
需要应用新宏值时，在 PID 页选第四项“恢复PID初值”：

1. 第一次中键（或右键）载入宏初值到 RAM 并预览，尚未写入 Flash。
2. 再按中键确认保存，成功提示 `SAVED OK`；左键撤销本次预览。
3. 若保存失败，仍停留在预览编辑状态，可重试或撤销；未确认就断电也不会替换旧 Flash 值。

恢复操作仅修改 Kp/Ki/Kd，不改变舵机三值、速度设定或失线阈值。
参数按标称 2ms 时间尺度计算：
`u = Kp*e + Ki*积分(e dt) + Kd*滤波后的 de/dt`，其中 e 为扣除居中参考并限幅后的 -1～1 偏差；遥测 e1000 则为 -1000～1000。
没有居中参考时仍允许静态 PID 初调，使用原始差比和；开始运行仍要求完成居中标定。电机始终关闭。
参数包含微分滤波、积分限幅和饱和抗积分累积。静态调参用于核对方向和初调，最终效果须以实车行驶为准。

### 开始运行

未完成电感标定时提示 `NEED CAL`，未完成本次居中标定时提示 `NEED CENTER`，均禁止启动。
两项均完成后渐进起步，按扣除居中参考的左右电感误差转向，并随偏差减小电机动力。
当前使用右后轮单编码器，TIM0 每 1ms 保存计数快照，前台每 2ms 测速并计算速度 PID；两电机使用同一动力命令，转向由舵机完成。编码器反馈是计数/10ms，PWM 仍为动力占空比，不是轮速。速度目标为 0 时显示 `NEED SPEED`，需先设置目标。
发车条件通过后发送 OLED 熄屏命令并取消未完成刷新。运行期间不绘图、不定位、不传输 OLED 数据；蓝牙遥测继续。失线、手动停车或其他故障退出运行时，先停执行器，再完整刷新故障/菜单画面并亮屏，避免闪出旧画面。

运行中左键或中键立即停车返回菜单，其余按键不改参数。ADC 超时/持续饱和、控制超时仍直接停车。弱信号先按以下条件确认，确认失线后停车并保留原因，必须手动再次发车。

- 运行有效失线门槛取 `min(已保存 lost_sum, 20)`，总强度低于此值进入确认，持续约 250ms 才停车。默认保存值 40 时，运行门槛为 20；居中标定和静态 PID 仍使用原保存值。
- 四路同时小于 5 时采用约 120ms 的连续近零确认。
- 确认期间保持上次有效舵机命令；电机动力只降低，不超过原值、CURVE 和 600 三者中的最小值，不会从静止自行起步。
- 进入弱信号后，总和需达到“运行有效失线阈值 + 10”（通常为 30）才恢复正常 PID 与渐进加速，避免阈值附近反复切换。恢复时清除旧 PID 积分/微分历史。

失线总强度参数合法范围由 `TRACK_LOST_SUM_MIN/MAX` 统一规定为 1～500；当前代码初值为 40，双路近零门槛为 15。有效 EEPROM 阈值仍优先。0 会使全零信号无法触发失线，因此禁止保存。此前低于 50 的合法现场设定会误报 `FLASH PARAM ERROR`，现已修复。

确认时间按标称 2ms 控制周期累计。运行门槛上限由 `TRACK_RUN_LOST_SUM_MAX` 控制；其余对应宏为 `TRACK_LOST_CONFIRM_MS`、`TRACK_ZERO_CONFIRM_MS`、`TRACK_LOST_RECOVER_MARGIN`、`TRACK_LOST_DUTY_MAX`；这项运行容错不放宽居中标定条件，也不延迟静态 PID 模式关闭弱信号舵机预览。
停车动作是两组电机输入置为相同高电平、取消电机 PWM 输出，同时关闭 P74 舵机脉冲并拉低。

十字候选通过双路共同增强和进入前接近直行判断，短时压制转向误差并减速；失线保护优先，十字状态不允许掩盖失线。
本次比赛不要求一圈自动停车，因此不加入启停线识别或计圈停车。

### 舵机设置 → 中值、左限位、右限位

电机始终不动。进入后舵机预览当前对应位置，上下调整，右键切换 1 / 10 步长，中键保存至 Flash，左键撤销未保存修改并退出。
屏幕显示当前值、已保存值、中/左/右三值。三值必须保持正确相对位置，不能互相跨越，不能超出绝对调试边界。

默认中值 760，左值 840，右值 670，频率为 330Hz（SPT5410LV，周期约 3.03ms）（一个单位约为 2us 脉宽；频率改变时三值对应脉宽保持不变）；绝对调试边界为 600～900。三值分别由 `TRACK_SERVO_DEFAULT_CENTER/LEFT/RIGHT` 定义；有效 EEPROM 记录仍优先。
这些只是保守初值与可调整边界，不代表当前机械结构已经验证允许转到边界。

### 标定设置 → 居中标定（车身参考）

每次上电按“电感标定 → 居中标定 → 开始运行”操作；舵机机械中值与本项电感参考分别设置。
居中标定页始终允许进入。若尚未完成本次电感标定，页内显示原始左右 ADC 和 `NEED SENSOR CAL`；中键直接转到电感标定，右键不会启动无效的居中采集。电感标定完成后，再进入居中标定采集车身参考。
必须先完成电感极值标定才能开始有效居中采集。将小车摆在直线赛道上，车身纵向对齐赛道、电感左右对称跨线，保持静止。
软件检查的是电感信号，不能自动判断车身是否摆正，摆放位置由操作者确认。

1. 中键开始采集 500 帧，约 1 秒；右键可重新采集。全程电机和舵机输出关闭。
2. 屏幕显示归一化 L/R、LM/RM、当前加权偏差 `E`、已保存参考 `REF`、进度 `N` 及结果；原始四路 ADC 可在电感标定页及串口查看。
3. 显示 `READY: OK TO SAVE` 后再次按中键，提示 `CENTER SAVED (RAM)`；左键返回菜单。
4. 取消、重采或失败都不会覆盖原已保存参考，只有成功确认才替换。

检查条件：两路归一化各不少于 100，总和不低于失线阈值（默认 40）；差比和偏差绝对值不超过 300；
采集期间偏差最大最小之差不超过 60；所有启用 ADC 通道不得饱和或超时。
不满足时分别显示信号弱、不稳定、偏离过大或 ADC 错误，调整摆放/检查接线后按中键或右键重试。
`SIGNAL TOO WEAK` 检查的是采集时的归一化 L/R；与原始 ADC 的最小标定跨度是不同条件。500 帧采集期间任意一帧不满足强度条件就会中止，之后应重新采集。
这些是初始检查阈值，可在 `track_config.h` 调整，仍需实车验证。

参考为 500 帧 `measuredE` 的算术平均值。控制误差变为：

`e1000 = clamp(measuredE - bodyRef, -1000, 1000)`。四路的 `measuredE` 使用论文 C4 加权公式，详见 FOUR_SENSOR_GUIDE.md；双路兼容模式仍使用差比和。

例如居中时 L=600、R=400、LM=RM，在当前默认权重下参考约为 200；后续相同信号的控制误差为 0。
该补偿不改变归一化量程，不改变真实失线判据，也不替代电感安装调平。
参考只保存在 RAM，不写 Flash，重启及成功重做极值标定后失效。

### 正常放大板的参数与计算

放大板故障已由用户更换，弱信号版本的检查阈值已恢复。原始 ADC 范围由每路实测标定决定，归一化仍为 0～1000，误差 E 为 -1000～1000。

| 检查项 | 当前值 | 对应含义 |
|---|---|---|
| 最小有效标定跨度 | 100 ADC | 每路 M-m 至少为 100 |
| 居中单路最低强度 | 100，归一化 | 每路至少达到各自量程的 10% |
| 保存的最低总强度 | 默认 40，归一化 | 静态模式沿用；运行取 min(保存值,20) |
| 普通弱信号确认 | 总和低于 min(保存值,20)，持续约 250ms | 短暂弱信号先保持转向并降速 |
| 四路近零确认 | 四路每路小于 5，连续约 120ms | 连续近零达到时间才停车 |
| 弱信号恢复门槛 | 运行有效阈值 + 10，通常总和 30 | 达到门槛后恢复正常控制 |
| 居中最大静态偏差 | ±300 | 允许一定安装差异，仍拒绝明显偏线 |
| 居中采集偏差极差 | 60 | 采集期间最大 E 与最小 E 的差 |

硬件 ADC 饱和阈值继续为 4090；十字强度继续使用归一化标度；PID、动力和舵机参数不因原始 ADC 量程小而按比例缩小。
EEPROM 中弱信号版本的默认失线阈值 100 在读取后调整为当前代码默认 40，手动保存时才写回；其他已保存阈值（例如 175）不强制改写，原 PID/方向/舵机/动力参数保留。

归一化与差比和改用有边界的整数商余递推；E 先计算非负差值的千分比，再恢复正负符号，避免此路径调用 32 位乘除库。居中均值也采用显式有符号处理。现有数学库及所有工程引用保留。
编译后链接调用关系已核对，`TrackNormalize`、`TrackSensors_Error`、居中均值路径不再调用 MDU 乘除入口。本次未证明旧 MDU 库在实机上的具体故障原因；烧录后仍需验证 E 的中间值。
每次上电执行 `TrackSensors_MathCheck()`，检查 0～80/0～10 归一化、正负中间误差和居中均值。失败显示 `MATH ERROR`，拒绝进入 PID、运行及居中采集页面。
软件测试覆盖 0～80 的全部 6561 组左右输入，以及实际页面字模。示例原始 ADC L=40/R=20、两路量程 0～80 时，归一化为 L=500/R=250，E=333；左右互换则 E=-333。

### 电机设置 → 速度设定、动力限幅；PID调参 → 速度闭环调参

速度设定里的 BASE/CURVE 是目标计数/10ms，初值均为 0；首次需设置非零 BASE。精调/粗调为 1/10，要求 `0 ≤ CURVE ≤ BASE ≤ 1000`。静态页面关闭所有输出，可手转右轮看反馈。
速度PID是独立 Kp/Ki/Kd，代码初值 30/30/0，可按原来的 0.01/0.10 步长修改并保存，第四项可只恢复速度增益初值。原转向 PID 参数编辑方式不变，两页统一从主菜单“PID调参”二级菜单进入。
动力限幅页面保留原 PWM BASE/CURVE 数值；本次用户代码初值为 3000/1500（30%/15%），有效 Flash 值优先。要求 `0 ≤ CURVE ≤ BASE ≤ 4000`，沿用 10/100 调整步长。它们只限制闭环最大动力，不等于目标速度。
各页均中键保存、左键撤销/退出，编辑及保存期间电机关闭。详细步骤与新遥测字段见 [SPEED_LOOP_GUIDE.md](SPEED_LOOP_GUIDE.md)。

### 舵机设置 → 舵机方向

此页及两个电机方向页全程关闭电机与舵机输出，不会因为选择方向而立即试转。
上键设为“正向”、下键设为“反向”、右键切换；中键保存到 Flash，左键撤销未保存修改并返回父菜单。
屏幕显示当前方向、`SAVED` 已保存方向及修改标志；保存失败可重试或左键撤销。

舵机正向表示占空比增大时逻辑上向左转，反向表示占空比减小时逻辑上向左转。
切换方向会交换左右限位的数值标签，中值和实际可用脉宽范围不变。例如 C=760/L=840/R=670，
改为反向后变为 C=760/L=670/R=840。取消修改会连同限位一起恢复；保存后也会一起掉电保留。
实际机构方向需架空确认；方向页本身不发舵机脉冲，可到中值/限位页核对。

### 电机设置 → 左电机方向、右电机方向

分别保存逻辑左、右轮的正反向开关，不会改变速度设置或另一轮方向。
“正向”是本工程默认驱动接线关系，“反向”交换对应电机两输入的 PWM 关系；实际前进方向由接线与安装决定。
保存后在下一次开始运行时使用新方向。修改或保存期间不启动电机；若启用了电机通道交换宏，方向设置随逻辑左右轮一起映射。

### 四电感配置

当前 `TRACK_SENSOR_COUNT=4`，数组保持 L、R、LM、RM，物理从左到右为 L、LM、RM、R。
中间引脚集中在 `TRACK_ADC_MIDDLE_LEFT_PIN`、`TRACK_ADC_MIDDLE_RIGHT_PIN`；当前为 P10/P05，请以实际接线核对。外侧仍为 P13/P01。
算法采用 [参考文章](https://blog.csdn.net/zhuoqingjoking97298/article/details/108993827) C4，四路分别标定、归一化，居中参考也由相同加权误差采集。A/B/C/P 在配置宏中调整，与 PID 增益分开。

具体公式、默认权重、分母保护、ADC 诊断与换舵机操作见 [FOUR_SENSOR_GUIDE.md](FOUR_SENSOR_GUIDE.md)。

## Flash 保存与烧录

使用 STC32G12K128 的片内用户 EEPROM，取从 FE0000 开始的前 1KB，分为两个 512B 扇区。IAP 接口使用从 0 开始的偏移，不能将程序区末尾当作可写 EEPROM。依据为 [芯片官方手册](https://www.stcmicro.com/datasheet/stc32g-cn.pdf) 第 18.2、18.3 节。

| 槽位 | IAP 偏移 | CPU 地址 |
|---|---|---|
| A | 0x000000 | 0xFE0000～0xFE01FF |
| B | 0x000200 | 0xFE0200～0xFE03FF |

Keil 链接器继续将 CODE、CONST、HCONST 限定在 0xFF0000～0xFFFBFF；HEX 校验脚本检查所有程序字节均在此范围，因此不会占用低地址的 EEPROM。保留的程序区末尾边界不再用作参数地址。
记录包含版本、序号、CRC16 和最后写入的有效标记。原 32B 基础记录后追加 32B SPD1 速度扩展，扩展也校验 CRC 并绑定基础序号/CRC；两段先写数据，最后提交基础有效标记。更新时擦写另一槽，旧槽保持有效，写后回读；参数未改变则不擦写。
PID、中值、左右限位、三个方向及动力作为一份一致的控制参数记录保存；电感极值和车身居中参考不保存到 Flash。
基础段仍为 v2、32 字节；方向位在第 26 字节。整条含速度目标/增益扩展后为 64 字节，仍放在原两个扇区，不额外占用 EEPROM。
兼容读取旧 v1：保留原 PID、舵机和 BASE/CURVE，由已有左右限位顺序推断舵机方向，左右电机使用代码默认方向。
在正确 EEPROM 槽位中读取旧 v1 参数不会自动擦写；下一次明确保存时才写入 v2，保留另一槽以防保存中途掉电。原错误地址不再读写；正确槽位没有有效记录时使用代码初值，不主动迁移原程序区末尾数据。

烧录时在 STC-ISP 的“设置用户 EEPROM 大小”中选择至少 1KB（当前代码位于 FF0000 起，EEPROM 不要超过 64KB），不能为 0。EEPROM 由工具从 FE0000 起分配，不是预留程序区末尾。程序时钟对应 33.1776MHz；IAP 等待参数按初始化后实际系统时钟向上取整 MHz 设置。
保存失败现在分别显示 `FLASH PARAM ERROR`、`FLASH OUTPUT ARMED`、`FLASH ERASE FAILED`、`FLASH WRITE FAILED`、`FLASH READ FAILED`、`FLASH VERIFY FAILED`。出现擦除失败时先核对 EEPROM 分配及烧录设置。IAP 硬件命令失败位为 `IAP_CONTR` 的 bit4（0x10）。
希望以后重新下载仍保留参数时，关闭下载器中擦除 EEPROM 的选项；若选择整片擦除，参数将恢复默认值。
更换方向配置或参数版本后，旧记录不合法会回退默认值；菜单显示 `DEFAULT`。保存成功后恢复 `READY`。
程序已经生成 HEX，尚未连接下载器烧录，也未实测当前芯片的 IAP 设置。

## UART 遥测

PID 调参及运行时每 500ms 输出一帧完整 CSV（2Hz），速度 PID 页面也输出完整 CSV；其余模式在切换/保存时输出 `#CFG` 参数快照。
蓝牙模块串口应设为 115200 / 8N1；串口和遥测间隔分别由 `TRACK_UART_BAUD`、`TRACK_TELEMETRY_MS` 配置。ADC 整帧触发为 1ms（1000Hz），控制周期为 2ms（500Hz），不随遥测降频。
115200 / 8N1 理论有效速率为 11520 字节/秒；当前完整遥测仍保持 500ms 一帧，发送周期可独立配置。本次保留原 39 列顺序，在原 41 列后追加 11 个速度字段，共 52 列；对应定义见 SPEED_LOOP_GUIDE.md。
上电输出的 `#` 表头与快照为元数据，上位机绘图时可跳过 `#` 行。发送有界队列拥塞时舍弃本次新帧并累计 drop，不阻塞控制。

| 字段 | 含义 |
|---|---|
| ms, mode | 毫秒时基；菜单=0，标定=1，PID=2，运行=3，中值=4，左限位=5，右限位=6，居中标定=7，速度=8，舵机方向=9，左电机方向=10，右电机方向=11，速度目标=12，速度闭环PID=13 |
| rawL, rawR, raw3, raw4 | 去极值均值后的 ADC，尚未归一化；顺序为 L、R、LM、RM |
| nL, nR, n3, n4 | 归一化 0～1000 |
| e1000 | 扣除居中参考并限幅后的控制误差 ×1000；十字状态可能暂时置零 |
| kp100, ki100, kd100 | 参数 ×100 |
| P10, I10, D10, U10 | PID 分量和限幅前舵机偏移 ×10；U10 含舵机方向符号 |
| servo, center, left, right | 舵机目标及限位，库占空比万分比单位 |
| pwmL, pwmR | 逻辑左/右电机动力，0～10000 |
| signal, fault, sat, drop, cal | 信号有效、故障码、限幅标志、丢帧累计、标定有效；运行中 signal=0、fault=0 可能处于弱信号限速确认，仍有受限输出 |
| bodyRef, bodyCal, measuredE | 居中参考、参考有效标志、扣除参考前的差比和偏差 ×1000 |
| base, curve | 新增在 CSV 末尾：当前基础动力及弯道最低动力，万分比占空比单位；也包含在 #CFG 中 |
| servoDir, leftRev, rightRev | CSV 末尾三个方向值：舵机为 +1/-1，电机为 0/1；也包含在 #CFG 中 |
| target1000 | 第 38 列，转向 PID 的位置目标 ×1000，正常循迹为 0，由 `TRACK_STEERING_TARGET1000` 定义 |
| feedback1000 | 第 39 列，电感估计的位置反馈 ×1000，即居中补偿后的四电感加权偏差，范围 -1000～1000 |
| adcFrames, adcOverruns | 第 40/41 列：完成整帧累计数（16 位回绕）、跨过下一毫秒触发的累计数（饱和 65535） |

反馈和控制共用 `TrackSensors_Feedback()`：`feedback1000 = clamp(measuredE - bodyRef, -1000, 1000)`，未提交居中参考时不减去 bodyRef。
例如 L=600、R=400、LM=RM，当前默认权重下 measuredE=200，已保存 bodyRef=150，则发送目标 0、反馈 50（实际标度为 0.050）。
本车保留原纠偏符号，送给 PID 的普通循迹误差为 `feedback1000 - target1000`，再由舵机方向确定输出符号；十字策略可能把 `e1000` 暂时置零，但不会覆盖真实反馈列。
`feedback1000` 是电感推算的横向偏差，不是舵机实测角度。结合 `cal`、`signal` 判断反馈是否有效；未标定或信号不足时不要将数值当作正常闭环反馈。

`#CFG` 还包含 `menu` 层级：0=主菜单，1=标定设置，2=舵机设置，3=电机设置，4=PID调参。

故障码：0=正常，1=未标定，2=ADC 错误，3=失线，4=控制超时，5=手动停车，6=参数非法，7=未做居中标定，8=整数计算自检失败，9=未设置速度，10=编码器读取/计数异常，11=有动力而持续无脉冲。
串口仅输出遥测，不接受远程驾驶或参数写入指令。
